LCS AUTH PERSISTENCE + SINGLE-SOURCE AUTH FIX — 2026-08-28

Fixed:
- Google/Firebase sessions are explicitly initialized with durable browser persistence (IndexedDB + localStorage).
- Google sign-in explicitly selects LOCAL persistence immediately before the popup operation.
- The site waits for Firebase authStateReady()/onAuthStateChanged before treating a null currentUser as a real signed-out state.
- Header/account UI reconciles against Firebase Auth currentUser instead of maintaining an independent login state.
- Account connection status now reports the actual Firebase/Google provider state.
- Explicit sign-out is distinguished from a failed session restore.
- A non-sensitive local marker is used only to detect that a previously saved session unexpectedly failed to restore; it is never treated as authentication.
- Existing signed-in sessions are normalized to durable local persistence after Firebase finishes its startup restore.
- Added cache-busting for the updated app module.

Security:
- No OAuth tokens, passwords, Google names, or email addresses are stored in the diagnostic marker.
- Firebase Auth remains the sole authority for whether the browser is authenticated.
- Public LCS profile identity remains separate from the private Google sign-in identity.
