DAI 3.3 · 10–15 MINUTE BUILD

Fire Native Runtime Content From Action JSON

Create a tiny ability that spawns a registered projectile, emits a particle, applies a temporary effect, then removes it later. This demonstrates the new first-class 3.3 dispatch path without a custom Java handler.

Scope general actionsAuthority server runtimeUses projectile + particle + effect

1. Create the native definitions

Use the Creator's DAI Content editor to create a projectile, particle and effect with stable namespaced IDs such as my_pack:arc_bolt, my_pack:arc_flash and my_pack:charged.

2. Dispatch them from one sequence

Objective action sequence
[
  { "type": "projectile_spawn", "action": "my_pack:arc_bolt" },
  { "type": "particle_emit", "action": "my_pack:arc_flash" },
  { "type": "effect_apply", "action": "my_pack:charged", "ticks": 100, "value": 1 }
]

effect_apply uses ticks as duration and value as amplifier. The server aliases (server_projectile_spawn, etc.) are equivalent when you want authority to be visually explicit.

3. Remove the effect

Cleanup action
{
  "type": "effect_remove",
  "action": "my_pack:charged"
}

For a potion definition, use potion_apply with the potion ID instead.

4. Test the authority boundary

  1. Creator testerValidate references and action flow.
  2. Singleplayer/integrated serverConfirm the registered runtime content exists and dispatch succeeds.
  3. Dedicated serverConfirm the same JSON remains server-authoritative.
Do not use entity behavior verbs here. wander, chase_target and similar entries belong inside native entity behavior definitions, not ordinary objectives.
