LCS v0.5 — SECURITY / SAFETY / CONNECTIONS / LFG

SECURITY ARCHITECTURE
- Firebase Auth UID is no longer used in any v0.5 public document.
- Added owner-only privateAccounts/{uid} -> random publicProfileId mapping.
- Public profiles and all public authored content reference only publicProfileId.
- Removed application use/display/storage of Google email, provider display name, and provider photo.
- Removed copied authorName/authorPhoto fields from public content documents.
- Legacy UID-bearing v0.4 collections are quarantined from public reads.
- Signed-in owners receive best-effort private migration of their own legacy records.
- Added CSP and no-referrer policy.
- Repository secret scan finds no private keys, service-account credentials, OAuth secrets, access tokens, refresh tokens, or GitHub tokens.
- Firebase Web App API key remains public client configuration by design; it must be API/referrer restricted in Google Cloud/Firebase.

CONNECTIONS
- Public profile following/follower system uses public profile IDs only.
- Private friend requests are readable only by sender/recipient.
- Accepted friendships remain private to both participants.
- Added owner-only blocking; Firestore denies new friend/LFG requests across blocked pairs.
- Deterministic friend request IDs prevent duplicate pending requests per pair.
- Connections dashboard shows friends, incoming/outgoing requests, followers, following, and LFG requests.

LFG
- Added Play Together / Create Together / Share Information listing types.
- LFG listings are public by design.
- No email/phone/private-contact fields exist in LFG.
- Obvious email/phone data is blocked in LFG description/availability fields client-side.
- LFG match requests are private to the listing owner and requester.
- Deterministic match request IDs prevent repeat requests to the same listing from the same profile.

DEPLOYMENT
Publish logicalcommunicationservice/firestore.rules after deploying the site.
The v0.5 client expects the v0.5 security rules and new public/private collection names.
