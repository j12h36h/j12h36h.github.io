Privacy Policy

Last updated August 28, 2026 · LCS v0.5.

Authentication boundary

LCS uses Firebase Authentication with Google sign-in. Google and Firebase handle the provider information required for authentication. LCS application code does not read, display, or write the Google account name, email address, provider profile photo, OAuth tokens, passwords, or provider credentials.

Private authentication ID

Firebase assigns an authentication UID. LCS uses that UID only as the document key for an owner-only privateAccounts record. That private record contains only a randomly generated public profile ID, a security schema version, and a creation timestamp. Firestore rules deny public access to the authentication UID mapping.

Public identity

Public profiles live under random public profile IDs and contain only a chosen display name, optional public bio, and timestamps. Public posts and other public records reference the random public profile ID rather than the Firebase authentication UID.

Public content

Posts, comments, communities, channels, ideas, problems, projects, Helpful reactions, public follows, project relationships, and LFG listings are designed to be visible to anyone. Do not put sensitive information into public content.

Friends and LFG requests

Friend requests, accepted friend relationships, and LFG match requests are stored in private Firestore collections. Rules allow reads only to the signed-in accounts whose public profile IDs participate in the relationship. LFG listings intentionally contain no email, phone, legal-name, or external credential fields.

Legacy quarantine

Version 0.5 moves public data into new collections that do not carry Firebase authentication UIDs. Older UID-bearing v0.4 collections are no longer publicly readable. A signed-in owner may privately migrate and delete their own legacy records.

Repository data

The GitHub Pages repository contains only static site code and Firebase Web App client configuration. Firebase Web App configuration, including its browser API key, is public client configuration and is not a server secret. Service-account keys, OAuth client secrets, private keys, access tokens, refresh tokens, provider personal information, and user account records must never be committed to the repository.

Local browser state

Firebase Authentication may store authentication state in the browser so a sign-in can persist across refreshes. LCS does not place provider email/name/photo data into its own local storage.

Third-party services

Authentication and database functionality use Google Firebase services and are also subject to Google's applicable privacy practices and terms.
