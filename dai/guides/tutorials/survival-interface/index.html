Build a Survival HUD

Create a clean custom survival interface that reacts to player state instead of hard-coding one static screen.

Inspired by [DAI] Survival Interface45–75 min5 milestones
Build the idea, not a clone. This workshop intentionally recreates a smaller learning version of the public project. It teaches the same categories of DAI systems without pretending to reproduce every private/internal project file.

What You Learn

HUD/UIconditionsplayer stateoverlaysresource packresponsive visibility

Starter Project Shape

Create only the folders you need for each milestone. The exact final tree can grow as you add your own systems.

Suggested learning layout
data/survival_hud/
├─ dai_objectives/
├─ dai_menus/        (optional)
└─ presentation definitions
assets/survival_hud/
└─ textures/gui/hud/

Build It in Milestones

  1. Choose three signalsStart with health, food and one status signal so the first HUD is easy to validate.
  2. Build the frameCreate the visual frame and anchors in the resource pack.
  3. Read live stateUse DAI conditions/state providers to decide which presentation branch should be visible.
  4. Separate visual statesCreate clear normal, warning and critical states instead of one overloaded design.
  5. Test gameplay visibilityCheck menus, world transitions and different resolutions so the HUD does not become the game itself.

Make It Yours

  • Add armor, air or custom attributes.
  • Create compact and cinematic layout variants.
  • Add project-configurable visibility toggles.
