DAI CREATOR · PUBLIC BASES

Start From a Public Pack

Clone a public DAI pack into the Creator, inspect every managed definition and preserve unsupported files while you learn or branch into a derivative project.

1. Open the public-base importer

In the Creator toolbar choose Use Public Pack as Base. Official choices now come from /api/public-bases.json, a dedicated source registry whose components point directly at GitHub raw ZIPs. The in-game installer keeps using /api/packs.json separately.

2. Import and inspect

Choose a project and component, then load it. The browser fetches the ZIP directly from the configured GitHub source URL and runs the normal importer: managed DAI definitions become editable forms while every unsupported file is preserved as a Universal File. The optional source note keeps provenance with the derivative project.

3. GitHub source troubleshooting

If an official entry fails with HTTP 404, the configured release ZIP has not been pushed to that GitHub path yet. If a custom host blocks browser access, download the ZIP and use the normal Import Datapack ZIP / Import Resource ZIP buttons.

4. Fork responsibly

Rename the namespace/stable pack ID when creating a distinct project, update resource references, and read the source project’s license before redistributing code/assets. A public download is not automatically permission to relicense or republish everything inside it.

Use the Creator: these schemas can be pasted into the type-specific JSON fields in DAI Content / Runtime Definitions. Unknown fields are preserved on import/export.
