Custom Content

Define content identities, registry-backed entries, entities, attributes, animations and processing data without writing experience-specific Java.

Content Identity Folders

KindFolderUse
Itemdai_itemsGeneral item identity and behavior metadata.
Blockdai_blocksBlock identity and optional native registry entry.
Weapon / Armordai_weapons / dai_armorEquipment-oriented metadata.
Effects / Potionsdai_effects / dai_potionsStatus and consumable identities.

Entitydai_entitiesEntity dimensions, rendering metadata, behavior sequence and natural spawn policy.

Carrier vs Registry-Backed

Most definitions can reuse a vanilla or modded carrier and remain reloadable. Set registry_backed: true only when you need a real DAI-created registry ID.

Static registries happen during startup. Registry-backed definitions must exist on disk early enough for DAI's registry scanner. Adding one after registration may require a restart before the native ID exists.

Entity Metadata

{
  "carrier": "minecraft:pig",
  "display_name": "Companion",
  "registry_backed": false,
  "entity": {
    "category": "creature",
    "width": 0.6,
    "height": 1.0,
    "texture": "my_pack:entity/companion",
    "behavior_sequence": "my_pack:companion_tick",
    "behavior_interval": 10,
    "vanilla_ai": true,
    "spawning": {
      "natural": false,
      "biomes": [],
      "placement": "on_ground"
    }
  }
}

Attributes & Animations

Attributes use dai_attributes with default/minimum/maximum values. Animations use dai_animations and can define duration, channel, priority, markers, marker actions and keyed body-part tracks.

{
  "default": 100.0,
  "minimum": 0.0,
  "maximum": 100.0
}

Processing Recipes & Other Data

DAI processing recipes live in dai_recipes. Screen profiles, reaction event definitions, menu systems and arbitrary Minecraft datapack JSON can live in the same pack. The Creator's Universal Files workspace exists specifically so the UI never becomes a limitation.
