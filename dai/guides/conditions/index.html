Conditions & Decision Making

Conditions ask questions about DAI's current context. They can gate atomic actions, filter Available-menu buttons, compare numeric/string/boolean values, and combine into nested logical groups.

204 registered provider conditionsPlus built-in logical groups.
Shared context snapshotA condition group evaluates against one captured context.
Composable logicUse all, any, none, not, comparisons, and negate.
DAI 1.8: This system now participates in the client/server architecture. Client-facing definitions can load locally; actions that mutate authoritative server state should use the server action layer.

Condition JSON Shape

General condition definition
{
  "type": "condition_type",
  "operator": "is_true",
  "boolean_value": false,
  "number_value": 0.0,
  "string_value": "",
  "negate": false,
  "parameter": "",
  "parameter_number": 0.0,
  "conditions": []
}

Most conditions need only a small subset of these fields.

Comparison Operators

Value typeSupported operators
Booleanis_true, is_false, equals, not_equals
Numberequals, not_equals, less_than, less_than_or_equal, greater_than, greater_than_or_equal
Stringequals, not_equals, equals_ignore_case, contains, starts_with, ends_with
Full health and hunger
{
  "conditions": [
    {
      "type": "player_health",
      "operator": "greater_than_or_equal",
      "number_value": 20.0
    },
    {
      "type": "player_hunger",
      "operator": "greater_than_or_equal",
      "number_value": 20.0
    }
  ]
}

A top-level conditions list uses AND behavior: every entry must pass.

Logical Condition Groups

GroupBehavior
allTrue only when every child condition passes. Empty all is true.
anyTrue when at least one child passes. Empty any is false.
noneTrue when none of the child conditions pass.
notRequires exactly one child and inverts it.
Any nearby opportunity
{
  "type": "any",
  "conditions": [
    {
      "type": "nearby_entity_count",
      "parameter": "animal",
      "operator": "greater_than",
      "number_value": 0.0,
      "parameter_number": 16.0
    },
    {
      "type": "nearby_recognition",
      "parameter": "decisions_and_impulses:tree",
      "number_value": 24.0
    }
  ]
}

negate: true can invert the final result of any provider or logical group.

Action Result Conditions

last_action_running

Previous/current status is RUNNING.

last_action_success

The committed previous action succeeded.

last_action_failure

The committed previous action failed.

last_action_cancelled

The committed previous action was cancelled.

last_action_timed_out

The committed previous action timed out.

Atomic runtime skip behavior: if an action's own runtime conditions fail, DAI skips the body and records FAILURE for that semantic action.

Reaction Event Context

Seven providers expose the event currently being evaluated by a Reaction. They are especially useful in the reaction definition's top-level conditions list because that list is evaluated synchronously while the event hook is active.

ConditionTypeMeaning
reaction_activebooleanA reaction context is active.
reaction_eventstringCurrent event ID.
reaction_phasestringpre, during, or post.
reaction_has_entitybooleanThe event exposes an entity.
reaction_entity_typestringEntity resource ID.
reaction_entity_livingbooleanThe event entity is living.
reaction_entity_healthnumberHealth of the living event entity.

Server Capability Conditions

Use these boolean providers before an objective requires server-authoritative actions. They currently report the same negotiated server capability under compatibility-friendly names.

dai_server_availableDAI server channel is available.
server_dai_availableAlias for server capability checks.
server_authority_availableRecommended semantic name when branching around privileged actions.

DAI 1.9 Customization & Interaction Conditions

Customization state

customization_exists, customization_active, and customization_count query the new 19-registry layer.

Block context

reaction_has_block, reaction_block_id, and block X/Y/Z expose use/break context.

Item context

reaction_has_item and reaction_item_id expose the held/used item for interaction reactions.

  "type": "customization_active",
  "target": "quest",
