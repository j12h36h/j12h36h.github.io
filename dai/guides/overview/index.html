Design With DAI 1.8

DAI 1.8 is a JSON-driven Minecraft game framework with explicit client and server execution. Build small reliable pieces, then compose them into complete experiences.

The 1.8 Mental Model

Player / Minecraft Client
        ↓
Recognition + Conditions
        ↓
Menus / Decisions / Reactions
        ↓
Objectives + Sequences
        ↓
Client Actions ─────── Server Actions
        ↓                    ↓
Input / UI / Camera     World / Inventory / Functions
        └────────── Minecraft State ──────────┘
DAI is the engine; your pack is the game. Use the visual Creator when a first-class editor exists, and use Universal Files when you need a DAI or Minecraft data type that does not yet have a dedicated form.

Start With Ownership

Client behavior

Input, look, navigation, menus, recognition and overlays belong to the physical client.

Server behavior

Persistent world changes, privileged functions, inventory grants and worldgen belong to server authority.

Shared definitions

Data schemas describe what should happen without forcing a physical side to load the other's classes.

What You Can Build

Automation Packs

Navigation, gathering, combat, building, crafting and contextual decision systems.

Game Experiences

Custom title screens, owned saves, world bootstrap, persistent progression and server-authoritative rules.

Content Packs

Data-defined content identities, entities, attributes, animation, effects and presentation assets.

Recommended Build Order

  1. Define the player-visible goal.
  2. Decide which state is client-observed and which changes require server authority.
  3. Create small objectives and verify each one.
  4. Add conditions and recognition instead of hardcoding assumptions.
  5. Wrap behavior in menus/reactions/experience startup.
  6. Add presentation assets after logic is reliable.
  7. Validate, export, test a clean world and test resume/reload behavior.
