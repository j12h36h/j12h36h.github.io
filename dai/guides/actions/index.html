Actions: The Building Blocks of DAI

An action is one instruction DAI knows how to execute. Datapacks combine actions into objectives, sequences, rotors, menus, builders, Survival systems, and other gameplay.

232 registered general actionsThe 3.0 ActionRegistry surface, kept separate from the native entity behavior vocabulary.
One shared JSON shapeIndividual handlers read only the fields they need.
ComposableActions can sequence, queue, branch into, and call other behavior.
DAI 1.8: This system now participates in the client/server architecture. Client-facing definitions can load locally; actions that mutate authoritative server state should use the server action layer.

The Action JSON Shape

General action definition
{
  "type": "action_type",
  "action": "string",
  "conditions": [],
  "sequence": [],
  "menu": "string",
  "open": "string",
  "yaw": 0.0,
  "pitch": 0.0,
  "direction": "string",
  "ticks": 0,
  "slot": 0,
  "state": false,
  "value": 0.0
}
Only provide the fields the selected action needs. The handler-specific parameters are listed in the catalog below.

Parameter Glossary

typeRegistered action handler ID.
actionGeneral string payload: resource ID, item/block/tag, waypoint, command, key, gamemode, or referenced action.
conditionsConditions evaluated immediately before the atomic action executes.
sequenceNested child actions used by sequence/random composition.
menuMenu category used by menu actions.
openSecondary string payload, commonly a menu ID.
yaw / pitchCamera angle or offsets.
directionMovement direction, spatial offset, or scan mode depending on the handler.
ticksDuration, timeout, or action-specific tick budget.
slotHotbar/container slot or generation identifier depending on handler.
stateBoolean on/off value.
valueGeneric numeric input such as radius, stop distance, or count.

Presentation Actions

DAI 1.6 also exposes screen presentation through normal action JSON. Static sprites and sprite sheets intentionally use separate schemas.

ActionPayloadPurpose
overlay_spritespriteAdd or replace a static resource-pack texture layer.
overlay_sprite_sheetsprite_sheetAdd or replace an animated frame-grid layer.
overlay_removeactionRemove one overlay by overlay ID.
overlay_clearnoneClear every active DAI overlay.
Texture assets are resource-pack content. A datapack can reference my_pack:gui/combat/pow, while Minecraft resolves the PNG from assets/my_pack/textures/gui/combat/pow.png in an enabled resource pack.

DAI 1.8 Server Actions

These actions cross the optional DAI client/server bridge and execute on the logical server when server authority is available.

ActionFieldsPurpose
server_run_functionactionRun a namespaced datapack function with DAI server authority.
server_set_blockaction, targetSet a block state directly on the server. target supports relative coordinates.
server_break_blocktarget, stateDestroy a block; state controls drops.
server_give_itemaction, valueGive an item/count to the acting player.
server_take_itemaction, valueRemove an item/count from the acting player.
run_server_commandactionCompatibility alias for a privileged server command request. Prefer dedicated server actions/functions when possible.
Example
{
  "type": "server_set_block",
  "action": "minecraft:lantern[hanging=true]",
  "target": "~2 ~ ~-1"
}

DAI 3.0 Runtime Actions

Available in 3.0: the generic action shape now drives runtime state/capabilities, references, attributes, animations, registered content, reaction events and authoritative entity status. These are searchable in the Universal Creator reference.

State + capabilities

state_set_boolean, state_set_number, state_set_string, state_add_number, state_toggle_boolean, state_clear, and capability_add/remove/clear.

References

Remember target/reaction entities, target blocks or player positions, then reference_select or reference_clear later.

Attributes + status

Custom attribute_*, native native_attribute_*, and server-authoritative status_* health/food/air/fire operations.

Animation + content

animation_play/stop/pause/resume, wait_for_animation, content_activate/deactivate/event/give, and emit_reaction_event.

{
  "type": "attribute_modifier_add",
  "action": "my_pack:power",
  "target": "selected",
  "direction": "berserk_bonus",
  "value": 0.25,
  "open": "multiply_total"
}

DAI 3.0 Customization Actions

DAI 3.0 includes three generic registry actions plus category convenience actions. Generic definitions use direction for the kind, action for the definition ID, open for an optional event override, target for runtime payload/coordinates, and value for a numeric payload.

{
  "type": "customization_event",
  "direction": "dialogue",
  "action": "my_pack:intro",
  "open": "choose",
  "target": "choice_2",
  "value": 0
}
