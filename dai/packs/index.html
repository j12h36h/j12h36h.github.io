DAI Engine 4.0: packs are now classified by runtime role: Experience Packs provide the primary experience, while Addons are reusable stackable systems. Existing namespaces and IDs remain stable where possible.

DAI Engine 4.0 Pack Model

DAI 4.0 no longer presents every datapack as one undifferentiated list. Each registry entry declares whether it is a primary Experience Pack or a stackable Addon.

EXPERIENCE PACKSComplete playable projects intended to provide the main rules, progression, world or gameplay experience. Normally one Experience Pack acts as the primary experience.
ADDONSReusable systems that can be layered onto an Experience Pack or used independently when supported: HUDs, effects, combat systems, automation, time systems and similar features.
DAI 4.0 registry: /dai/api/packs-4.0.json. The older /dai/api/packs.json remains the DAI 3.x CurseForge-file-ID installer registry and is not replaced by this update.

    ↓

    ↓
DAI changes only files it owns
Normal companion ZIPs can auto-enable through matching namespaces or explicit dai.auto_enable / dai.companion_id metadata. Stable IDs allow renamed/versioned updates without disturbing unrelated resource packs.

Learn From a Public Pack

The DAI Creator can use public packs as editable starting bases. The Creator now reads a dedicated GitHub-backed /api/public-bases.json registry instead of constructing browser downloads from CurseForge file IDs; direct public ZIP URLs still work too.

Derivative-work reminder: importing a public ZIP is a technical convenience, not a license grant. Keep source attribution and follow the pack's license before publishing modified code/assets.
