DAI 1.8.3

A JSON Game Framework for Minecraft

Decisions and Impulses provides reusable runtime capabilities on the client and logical server. Datapacks define behavior and authoritative game rules; resource packs define presentation assets; DAI connects them.

Current in 1.8.3: DAI keeps the 1.8 client/server architecture and adds a global datapack library, automatic experience deployment, experience-owned grave/backtick UI controls, and deeper runtime/process diagnostics.

Engine, Not One Fixed Game Mode

DAI Java Runtime = reusable engine + side-safe execution
Datapack = gameplay, logic, state, world rules
Resource Pack = textures, models, sounds, presentation assets
Creator = visual editor + universal pack/file builder

That means a third-party pack can be a tiny automation, a UI system, a custom content library, or an entire standalone Minecraft experience without requiring experience-specific Java.

Global Datapack Library

DAI 1.8.3 adds <gameDir>/datapacks/ as an install library parallel to Minecraft's global resource-pack folder. DAI scans supported experience data there early, but does not enable every global datapack in every save.

Install once

This gives creators resource-pack-like installation convenience without bypassing vanilla's world-local datapack loading model.

Server-Authoritative JSON Actions

DAI 1.8 distinguishes ordinary player commands from actions that require server ownership.

Player authority

run_command behaves like the player typed a normal command. Server permissions still apply.

DAI server authority

server_run_function, server_set_block, server_break_block, server_give_item and server_take_item execute through the DAI server layer when available.

Privileged client-originated mutation is intentionally restricted on dedicated servers. Integrated singleplayer can trust its local DAI client; multiplayer experiences should use server-approved capabilities rather than arbitrary remote privilege.

Client-Only Compatibility

DAI-specific payloads are optional. The client checks whether the connected server negotiated DAI support before sending authoritative requests. If the server does not expose DAI, client automation and presentation can continue operating where they do not require server authority.

Launchable Experiences

Experience definitions can own a save, choose whether to create/load it, select a DAI worldgen profile, define first-join and resume actions, and control experience UI behavior. In 1.8.3 an experience can own the grave/backtick key with explicit open/close actions and an anchor overlay, so a complete game can replace DAI's generic menu cleanly. Worldgen profiles can select a normal Minecraft world preset, seed, spawn, structures, generation commands and bootstrap actions.

Custom Content & Registries

DAI can load datapack-defined content identities for items, blocks, weapons, armor, effects, potions, projectiles, particles, enchantments and entities, plus attributes and animations. Definitions can remain reloadable aliases around existing carriers, or opt into registry-backed native content when static registry creation is required.

Native registry content is startup-sensitive. Registry-backed definitions must be visible during early scanning. Non-registry-backed identities remain much more flexible and are preferred when a vanilla/modded carrier is sufficient.
